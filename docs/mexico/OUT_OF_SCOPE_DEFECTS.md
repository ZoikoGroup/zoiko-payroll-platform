# Out-of-scope defects found during the Mexico build

These are pre-existing defects in **other** jurisdictions that came up while tracing touchpoints for Mexico. Master-prompt rule 8 says "zero behavior change for any other jurisdiction", so none of them are fixed on the Mexico work. Each one needs its own ticket.

The line numbers are from `nikhil` @ dce5279 (2026-10-15).

| ID | Area | Defect | Evidence | Likely impact | Suggested fix |
|---|---|---|---|---|---|
| OOS-1 | NL engine / API | Nothing handles `NLError`. `engine/resolver.py:101–111` raises `NLError("NL_SIMPLE_MODE_UNSUPPORTED", …)`, and no exception handler is registered for it in `app/main.py` or `app/core/exceptions.py`. `NLError(Exception)` is defined at `engine/countries/netherlands.py:62`. | grep across `main.py` and `core/exceptions.py`: no `NLError` handler. The handler at `main.py:125/149` covers `MissingComplianceConfigurationError` only. | A Dutch simple-mode calculation most likely returns an HTTP 500 instead of a coded 4xx. *Inferred from code, not reproduced.* | Raise `NetherlandsCalculationBlockedError` (a subclass of `MissingComplianceConfigurationError`) in resolver.py, or register a handler for `NLError`. Add a test that posts a simple-mode NL calculation and expects a 4xx with the code. |
| OOS-2 | Engine fallback registry | `NL_NO_FALLBACK` is undefined. Every NL row in `engine/fallback_registry.py:400–419` has `attr: "NL_NO_FALLBACK"`, but `engine/countries/netherlands.py` defines no such attribute. `getattr(…, None)` at about L493 silently returns None. | `grep -rn "NL_NO_FALLBACK\s*=" backend/app` finds nothing. | The fallback-defaults page shows null for NL. That is the intended value, but only by accident: the registry can no longer detect a renamed or removed attribute. | Define `NL_NO_FALLBACK = None` in `netherlands.py`, and add a registry test asserting that every `attr` resolves with `hasattr`. |
| OOS-3a | Frontend taxability matrix | `components/jurisdiction/TaxabilityMatrixTab.jsx:21–35` `PROGRAMS_BY_COUNTRY` only has CA and US. L98 falls back to CA, so any other country, including AU today (via `australiaComplianceConfig.jsx`), is shown Canada's programs. | Code read. | AU Super Admin sees Canadian program columns in the Taxability tab. | Add AU programs, or render an explicit "not configured for this country" state instead of falling back to CA. |
| OOS-3b | Frontend statutory routes | `pages/JurisdictionStatutory/index.js:33–37` derives its route map from the compliance map and only filters out `["FR","CH"]`. IT and SA therefore get statutory-rate links, but `ITStatutoryPage` and `SAStatutoryPage` do not exist. | Code read. | Dead links or a blank route for IT and SA on the Statutory Rates landing page. | Add IT and SA to the filter, or build the pages. |
| OOS-3c | Golden fixtures | `service.py:19274` maps `"NL": "nl_golden"` in `_GOLDEN_FIXTURES_DIR_BY_COUNTRY`, but `backend/tests/fixtures/nl_golden/` does not exist. | OOS-5 | Pack governance (shared) | **Approving a Draft pack moves it straight to Approved, skipping the transition graph.** `service.set_jurisdiction_pack_approver` (its "Draft → Approved" auto-advance) moves a Draft **tax** pack to Approved for any Super Admin who did not last edit it. A fix for everyone would stop the auto-advance for countries in `_PACK_TRANSITION_GRAPH_COUNTRIES`: record the approver, keep the status. That needs its own ticket and its own tests per country. |
