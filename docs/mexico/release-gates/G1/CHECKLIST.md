## Evidence checklist

Each item is tagged: **PRE-PILOT** (produced before any real Mexican data, from sources, synthetic cases or a test environment), **PILOT-GENERATED** (produced by the non-binding pilot, Phase 10e), or **GO-LIVE CHECK** (a real filing or payment, possible only after general availability; checked in the activation runbook, not gate evidence).

- [ ] **[PRE-PILOT]** Every ISR, subsidy and special-pay rule transcribed from its saved source, in an Approved pack (rows source-linked)
- [ ] **[PRE-PILOT]** Golden cases: ordinary, aguinaldo, PTU, vacation premium, finiquito / liquidación and an annual adjustment, each matched to an independent calculation
- [ ] **[PRE-PILOT]** CFDI 4.0 / Nómina 1.2 documents generated by Zoiko from synthetic data validated by the contracted PAC's test environment (stamp, cancel, replace)
- [ ] **[PRE-PILOT]** The CFDI schema release and catalog release Active, from S28 / S30
- [ ] **[PRE-PILOT]** The PAC contract and credential custody (CSD) recorded
- [ ] **[PRE-PILOT]** Re-download S4, S28 and S30 directly from sat.gob.mx (over a VPN or by a colleague in Mexico) and confirm the SHA-256 of each file matches the archive copy recorded in `docs/mexico/sources/SOURCES_MANIFEST.csv` (status `ARCHIVE_COPY_VERIFIED`, Phase 11a: sat.gob.mx did not resolve from Zoiko's network). Do it with `python -m scripts.verify_mexico_sources verify CODE downloader=NAME [file=F]`, which records the result; a mismatch blocks this gate until the pinned set is rebuilt from the direct download.
- [ ] **[PRE-PILOT]** **Evidence: `docs/mexico/sources/VERIFICATION_LOG.csv`** (Phase 11d). Every source this gate needs (above) is `VERIFIED` in the manifest **and** has a `MATCH` entry in the log: downloader, timestamp (UTC), official URL, final URL after redirects, response size and SHA-256. A status of `VERIFIED` can be set only by `verify`, from a fresh direct download that hashes to the saved copy, never from an archive capture. A `VERIFIED` row without its log entry fails the `sources_verified` activation check. Attach the log rows to the evidence pack.
- [ ] **[PRE-PILOT]** The employment subsidy in the CFDI (`SUBSIDY_APPLIED`): the saved S4 guide is the 2023 edition and cites the 11 December 2013 subsidy decree (S4 pp. 25, 68, 70), so it likely predates the 2024 subsidy reform. Save SAT's current instructions for reporting the subsidy in the nómina CFDI as a new source; only then can the `SUBSIDY_APPLIED` mapping be proposed and approved (Phase 11b: it stays unmapped, and a receipt with a subsidy is refused).
- [ ] **[PRE-PILOT]** **Pay frequency 01 Diario (decision for the payroll specialist, recorded 2026-10-26).** S28 code 01 Diario is deliberately not mapped to an Art. 96 period, so a daily-paid employee blocks (`MX_PAY_FREQUENCY_MAPPING_MISSING`). S2 B.I is headed "en función de la cantidad de trabajo realizado y no de días laborados… calculada en días", and RMF rule 3.12.2 (S1, PDF p. 425) only says to apply "las tarifas correspondientes del Anexo 8". Neither says a daily pay frequency uses B.I. Decide whether 01 maps to DAILY (B.I), and record the reasoning in the transcription log (TL-PER-1).
- [ ] **[PRE-PILOT]** **Rounding rule (`mx_rounding_rule`): a decision for the G1 owner.** It blocks every calculation. The candidate sources and what each says are in `MEXICO_TRANSCRIPTION_BATCH_2_REPORT.md` §3.
- [ ] **[PRE-PILOT]** The decisions the CFDI builder refuses without (Phase 11b report §7): the source of `SalarioDiarioIntegrado`, the `INFONAVIT_CREDIT`, `VACATION_PAYOUT` and annual-adjustment refund mappings, and how a separation receipt is validated (TipoRegimen 13, S4 pp. 34–35) — settled against the PAC's test environment
