# Poland release gate G4 — Filing and settlement

**Owner:** Integration + Payroll Ops  
**Evidence tag:** `PL-GATE-G4` (a SourceArtifact reviewed by someone other than its uploader)  
**Spec rule:** NO-GO if retry or correction is not idempotent and auditable.

The gate passes only when every check below is met and the evidence is recorded. `poland_readiness.pl_readiness()` re-derives this on every request (Super Admin → Poland → Release gates, or the `readiness` block of `GET /api/payroll/poland/summary`); nothing is ticked by hand.

## Checks

- [ ] Every in-scope form (DRA, RCA, RSA, ZUA, ZZA, ZWUA, PIT-11, PIT-4R) has an archived schema version in `poland_content.PL_FORM_SCHEMA_CATALOG` (`form_schemas_archived`, PL-019). Until then a filing is a canonical preview and approval is refused (`FILING_SCHEMA_MISMATCH`).
- [ ] The due-date and reconciliation rows are signed (`pl_zus_due_day_classes`, `pl_pit_remittance_due_rule`, `pl_pit11_*`, `pl_pit4r_due`, `pl_ppk_transfer_day`, `pl_reconciliation_tolerance`).

## Evidence to record

The ZUS / e-Deklaracje form versions, the chosen submission path (no live transport in the platform, D-5), a submission / rejection / correction rehearsal with receipts, and an NRS / tax-micro-account settlement reconciliation (AC-PL-05).
